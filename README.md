# FastAPI Base

A reusable FastAPI modular-monolith starter with authentication, user profiles,
PostgreSQL persistence, Alembic migrations, and a tested layered architecture.

## Included

- Email and password sign-up/sign-in.
- JWT access and refresh tokens.
- Current-user profile endpoints.
- FastAPI dependency injection with request-scoped SQLAlchemy sessions.
- Repository, service, schema, and route layers.
- PostgreSQL 15 through Docker Compose.
- Alembic migrations.
- Ruff linting/formatting and pytest coverage.
- Optional OpenRouter strategy and Opik observability wrapper.

## Requirements

Choose one development path:

- Docker and Docker Compose.
- Python 3.12+ and [uv](https://docs.astral.sh/uv/), with PostgreSQL available
  separately.

## Quick Start With Docker

1. Create the environment file:

   ```bash
   cp .env.example .env
   ```

2. Replace `SECRET_KEY` in `.env` with a secure random value:

   ```bash
   openssl rand -hex 32
   ```

3. Build and start the API and PostgreSQL:

   ```bash
   docker compose up -d --build
   ```

4. Apply migrations:

   ```bash
   docker compose exec api alembic upgrade head
   ```

5. Open the application:

   - API: `http://localhost:8000`
   - Swagger UI: `http://localhost:8000/docs`
   - ReDoc: `http://localhost:8000/redoc`
   - Health check: `http://localhost:8000/`
   - API ping: `http://localhost:8000/api/v1/ping`

View logs or stop the stack with:

```bash
docker compose logs -f api
docker compose down
```

To remove the local database volume and start from an empty database:

```bash
docker compose down -v
```

## Local Development

1. Install dependencies:

   ```bash
   uv sync
   ```

2. Create `.env`:

   ```bash
   cp .env.example .env
   ```

3. Update `DATABASE_URL` for PostgreSQL running on the host:

   ```env
   DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5433/fastapi_base
   ```

   To use only the bundled PostgreSQL container while running the API locally:

   ```bash
   docker compose up -d db
   ```

4. Replace `SECRET_KEY` with a secure value, then apply migrations and start
   the API:

   ```bash
   uv run alembic upgrade head
   uv run uvicorn app.main:app --reload --port 8000
   ```

The Compose database publishes PostgreSQL on host port `5433`.

## Environment Variables

| Variable | Purpose | Default/example |
| --- | --- | --- |
| `ENV` | Runtime environment | `dev` |
| `APP_NAME` | OpenAPI/application title | `FastAPI Base` |
| `PROJECT_NAME` | Machine-readable project name | `fastapi-base` |
| `SECRET_KEY` | JWT signing secret | Required |
| `DATABASE_URL` | SQLAlchemy database URL | PostgreSQL URL |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Access-token lifetime | `30` |
| `REFRESH_TOKEN_EXPIRE_MINUTES` | Refresh-token lifetime | `10080` |
| `BACKEND_CORS_ORIGINS` | JSON array of allowed CORS origins | `["http://localhost:3000"]` |
| `OPENROUTER_API_KEY` | Optional OpenRouter credential | Empty |
| `OPIK_PROJECT_NAME` | Optional Opik project | `fastapi_base` |

See [.env.example](.env.example) for the complete local template.

## API Overview

All application endpoints are under `/api/v1`.

| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/auth/sign-up` | Create a user |
| `POST` | `/auth/sign-in` | Issue access and refresh tokens |
| `POST` | `/auth/refresh` | Refresh an authenticated session |
| `GET` | `/users/me` | Read the current profile |
| `PATCH` | `/users/me/profile` | Update the current profile |
| `GET` | `/ping` | API v1 health check |

Normal API responses use:

```json
{
  "success": true,
  "data": {},
  "message": "Operation completed successfully"
}
```

## Database Migrations

Create, review, and apply a migration:

```bash
uv run alembic revision --autogenerate -m "Describe change"
uv run alembic upgrade head
```

Docker equivalents:

```bash
docker compose exec api alembic revision --autogenerate -m "Describe change"
docker compose exec api alembic upgrade head
```

Never keep an autogenerated migration without reviewing its upgrade and
downgrade operations.

## Project Structure

```text
app/
  api/v1/              API router registration
  common/              Shared models, schemas, repositories, UnitOfWork
  core/                Configuration, database, security, exceptions
  modules/
    auth/               Authentication routes, schemas, and services
    users/              User routes, services, repositories, and models
migrations/             Alembic environment and revisions
tests/                  Architecture, auth, and common-component tests
docs/handbook/          Repository architecture and development rules
```

The primary dependency direction is:

```text
endpoint -> service -> repository -> model
```

Read [docs/handbook/00_index.md](docs/handbook/00_index.md) before extending
the base project.
